## Build wissel: v0 scaffold

**Objective.** Wissel is a router for a fleet of coding agents and
skills — not another orchestrator like agetor. It decides which agent or
skill handles a task; it doesn't spawn worktrees or manage kanban columns
itself. Build a v0 CLI-only scaffold: a task goes in, the router picks an
agent (or says it can't, confidently), and the decision is always visible
and overridable.

**Context.** Full design rationale, the category research behind it, and
UI mockups (fleet view, routing panel, cost view, decision/plan-approval
view, project overview, investigations view) live here — read before
starting, they resolve most "why did we choose this" questions:

- Design record: Wissel — Architecture Decision Record
- UI mockups: Wissel — Fleet View & Routing Panel canvas
- Related project (keep the telemetry schema compatible with it): AI Agent
  Cost Control — Project Brief

**Decisions to honor** (don't relitigate these, just build to them):

1. Define agent/skill capability as data first — inputs, outputs, cost
   profile, trust level, tool access — before any routing logic touches
   it. This is the contract everything else depends on.
2. Routing v0 is rule-based (task type/keyword → agent mapping). No LLM
   classifier yet.
3. Every dispatch decision logs `{agent, model, task_id, estimated_cost,
   actual_cost}` from the first prototype, even before anything reads it.
4. One headless daemon; the web UI is the primary client for v0 — not
   CLI, not deferred. Build the daemon's HTTP+SSE API first, then a
   minimal web front end consuming it. A CLI can follow later as a second
   client of the same API; don't couple the router logic to either
   presentation.
5. Never auto-dispatch a low-confidence match. Zero match, weak match, or
   an unresolved tie all stop before spend, not after — see the ADR's
   "No-confident-match fallback" section for the exact rules.
6. Every routing decision shows what matched and why, in the same output,
   always — `wissel why <id>` per the ADR's mockup. This is not optional
   polish; it's the difference between a router and a black box.

**Do this first, in order:**

1. Write the capability spec (a markdown or JSON schema is fine) for what
   an "agent" and a "skill" are.
2. Pick 2 agent kinds and 3–4 skills. Wire up the simplest possible
   rule-based matcher between them.
3. Get one task through submit → route → dispatch → result end to end,
   for a real agent kind, before adding more.
4. Add the cost/telemetry log at the dispatch point (schema above), even
   with nothing reading it yet.
5. Implement the no-confident-match stop (item 5 above) — this is not a
   later nice-to-have, it's what keeps v0 safe to actually use.
6. Build the fleet view and routing decision panel as web views consuming
   the daemon API — match the ADR's mockups (canvas link above) in shape
   and, where reasonable, styling.

**Acceptance criteria for v0:**

- A task submitted via the web UI is routed to one of the wired-up
  agents, or explicitly refused with a reason — never silently guessed.
- The fleet view (web) shows real task status, not a mock.
- The routing decision panel shows the actual matched rule and the
  alternatives that were considered.
- Every dispatch has a cost record, even if the number is estimated.

**Out of scope for v0** — do not build these yet:

- A CLI client. Web is primary for v0 — add a CLI later, once the API is
  stable, as a second client of the same daemon.
- LLM-based routing fallback.
- The investigation-track fallback (spawning research subtasks on
  no-match) — land the simpler "stop and report" version first; the
  ADR's investigation-track design is there for when v0's simpler stop
  proves too blunt, not before.
- Sandboxing beyond what the underlying agent CLI already does. Note
  this as a known gap in the README, don't solve it here.
- Memory-informed routing (the `[[claude-mem-networked]]` integration).
  Routing stays rule-only until v0 works end to end.

Ask before proceeding if the capability spec design in step 1 forces a
routing-logic decision not covered above — everything else, use judgment
and keep moving.
